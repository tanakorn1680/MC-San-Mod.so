# GTA SA × Minecraft Mobile — สถานะและวิธีทดสอบ

เป้าหมาย: ให้ Minecraft ทำงานคู่กับ GTA San Andreas บนมือถือ Android ซิงก์เรียลไทม์ (Steve กล้อง บล็อก ม็อบ เอฟเฟกต์
ในโลก GTA และโต้ตอบกับรถ/คนเดินถนน) — ไม่ใช่แค่เลียนแบบหน้าตา

รายละเอียดหลักฐาน/สถาปัตยกรรม/ข้อมูลที่ขาด: `docs/findings.md`

## สิ่งที่มีตอนนี้ (MCBridge 0.3 — ฝั่ง GTA เท่านั้น)

- ปลั๊กอิน AML `libMCBridge64.so` ทำงานบน game thread (ฮุก `CClock::Update`) และหาฟังก์ชันเกมด้วยชื่อ
- เปิดเซิร์ฟเวอร์ `127.0.0.1:47800` ส่งตำแหน่งผู้เล่น ~10 ครั้ง/วินาที และรับคำสั่งทดสอบ
- เขียน log ทุกขั้นลง `Android/data/com.rockstargames.gtasa/files/MCBridge/`
  - `last_action.txt` 14 ขั้นล่าสุด (เขียนทับทุกครั้ง รอดแม้เกมเด้ง) · `previous_session.txt` ของรอบก่อน
  - `session.log` ล็อกเต็มรอบนี้ · `previous_session.log` ของรอบก่อน
  - `config.txt` สร้างให้ตอนรันครั้งแรก แก้ได้บนมือถือ (พอร์ต, เปิด/ปิด self test, **เปิด/ปิดเมนู `menu=1/0`**, ชื่อโมเดลที่จะลองค้น)
- **ใหม่ใน 0.3: เมนูในเกมของ MCBridge เอง** (ปุ่มวงกลมสีเขียว "MC" ลากย้ายได้) ไม่เกี่ยวข้องกับ menusan/ProMenu เลย
  - **Status / สถานะ** — ความคืบหน้ารวม, สถานะตอนนี้ (เกม, เซิร์ฟเวอร์, ไคลเอนต์, ข้อมูลที่ส่งรับ, ตำแหน่งผู้เล่น) และ "ขั้นถัดไป"
  - **Progress / ความคืบหน้า** — 11 ขั้น แต่ละขั้นเป็น สำเร็จ/รอ/ยังไม่ทดสอบ/ล้มเหลว/ยังไม่เริ่ม พร้อมหลักฐานและสิ่งที่ขาด
  - **Tests / ทดสอบ** — ปุ่มตรวจชื่อโมเดล, สร้างคนเดินถนน, สร้างวัตถุ (เสี่ยง ต้องแตะสองครั้ง) ทำได้จากมือถือโดยไม่ต้องใช้ Termux
  - **Log / ล็อก** — อ่านไฟล์ log ของตัวเอง + ปุ่ม **บันทึกรายงาน** รวมตารางความคืบหน้าและ log ทั้งหมดไว้ใน `MCBridge/report.txt`
    (เปิดด้วยตัวจัดการไฟล์แล้วส่งกลับมาได้เลย)
  - **Settings / ตั้งค่า** — ภาษา English/ไทย, รีเซ็ตตำแหน่งปุ่ม, ข้อมูลเวอร์ชัน/ตัวนับ
  - ไฟล์ที่เมนูสร้างเพิ่ม: `menu.cfg` (ภาษา+ตำแหน่งปุ่ม), `progress.txt` (ขั้นที่เคยพิสูจน์ได้จริงบนเครื่องนี้ + จำนวนรอบ), `report.txt`

**หลักการของเมนู:** แต่ละขั้นเป็น "สำเร็จ" ได้จากหลักฐานสดเท่านั้น (ตัวนับ, ผลทดสอบ, ซ็อกเก็ตที่ต่ออยู่) ขั้นที่ยังไม่มีโค้ด (วาดบล็อก, Steve/ม็อบ,
กล้อง/เอฟเฟกต์) จะเป็น "ยังไม่เริ่ม" เสมอ และ Minecraft จะนับว่าเชื่อมต่อแล้วก็ต่อเมื่อไคลเอนต์ส่งบรรทัด `ID minecraft <เวอร์ชัน>` มาเอง
(ตัวทดสอบอย่าง `bridge_probe.py` ส่ง `ID bridge_probe` จึงไม่ถูกนับเป็น Minecraft)

**สถานะการตรวจ:** 0.2 build ด้วย NDK ผ่านและรันในเกมแล้ว (มี log จากมือถือยืนยัน) ส่วนเมนูของ 0.3 ตรวจแล้วเฉพาะ syntax/การลิงก์บน ARM ด้วย header จริงของ
ImGui + AML และตรรกะความคืบหน้าบน Linux — **ยังไม่เคย build ด้วย NDK และยังไม่เคยรันในเกม**

## ขั้นตอนทดสอบ

1. อัปโหลดไฟล์ในชุดนี้ขึ้น repo (branch `main`) → Actions จะ build เอง (หรือกด Run workflow) — `mod/setup.sh` ดึง ImGui v1.91.9 + AML ให้เอง
2. ดาวน์โหลด artifact `libMCBridge64` วางใน `Android/data/com.rockstargames.gtasa/mods/`
   ถ้า build พัง ส่งไฟล์ artifact `build-log` (หรือข้อความใน "First build errors") กลับมา
3. เข้าเกม แตะปุ่มเขียว "MC" เปิดเมนู (ปุ่มไม่ขึ้น = ดู `last_action.txt` บรรทัด `menu: ...` ว่า hook ติดตั้งไหม)
4. เดินในที่โล่ง รอประมาณ 10–20 วินาที (self test: อ่านตำแหน่ง, ค้นชื่อโมเดล, spawn คนเดินถนน 1 คนข้างๆ) แล้วดูแท็บ Status/Progress
5. ส่งกลับมา: ไฟล์ `MCBridge/report.txt` (กด Log → บันทึกรายงาน) — ถ้าเกมเด้งก่อนเปิดเมนูได้ ส่ง `last_action.txt` + `previous_session.txt` แทน
6. ถ้าเปิด ProMenu (menusan) คู่กัน: ปุ่มของ MCBridge สีเขียวอยู่ซ้าย ปุ่ม ProMenu สีน้ำเงินอยู่ขวา — **ยังไม่เคยทดสอบสองตัวพร้อมกัน** ถ้าเกมเด้งหลังเพิ่มเมนูนี้
   ให้ตั้ง `menu=0` ใน `MCBridge/config.txt` แล้วลองใหม่ เพื่อแยกว่าเมนูเป็นต้นเหตุหรือไม่
7. ทดสอบสะพานจากภายนอก (Termux, ไม่บังคับ): `python tools/bridge_probe.py --send PING --send SPAWN_PED --seconds 5`

คำสั่งที่รับ: `ID <ชื่อ> <เวอร์ชัน>`, `PING`, `SPAWN_PED`, `SPAWN_OBJ <ชื่อโมเดล>` (วัตถุเสี่ยงกว่า ปิดไว้ใน self test; เปิดด้วย `selftest_obj=1`)
คำสั่ง `SPAWN_*` ทำเฉพาะตอนกำลังเล่น นอกนั้นตอบ `ERR ... not playing`
